### 1. 规划者至关重要！面向长时程规划的高效非均衡多智能体协作框架
**（Planner Matters! An Efficient and Unbalanced Multi-agent Collaboration Framework for Long-horizon Planning）**

🔗 https://arxiv.org/abs/2605.02168
📅 2026-05-04 | cs.AI / cs.LG / cs.MA

💡 **核心贡献**
将 Agent 自动化拆解为三个角色（规划者 + 执行者 + 记忆管理器），通过系统性计算分配分析发现**规划是影响任务成败的主导因素**，而执行和记忆管理只需较少算力即可达到竞争性结果。提出以规划者为中心的强化学习方法，利用 VLM-as-judge 对轨迹级奖励独占优化规划器，其余组件冻结。

🔧 **技术亮点**
- 三角色解耦架构：Planner（高层决策）/ Actor（任务执行）/ Memory Manager（情境推理）
- 非均衡计算分配：将模型容量集中投给 Planner，Actor/Memory 使用轻量模型
- 轨迹级 RL 训练 + VLM-as-judge 自动奖励，无需人工标注

📊 **实验结果**
在 web navigation、OS control、tool use 三大基准上均验证：将算力集中于 Planner 可带来稳健且高效的长时程自动化提升；代码已开源。

🎯 **与 Agent/Routing 的关联**
直接证明 Multi-Agent 内部的"算力路由"——将计算资源非均衡地分配给最关键角色（Planner）是提升长时程任务的核心策略。

### 2. LongSeeker：面向长时程搜索 Agent 的弹性上下文编排
**（LongSeeker: Elastic Context Orchestration for Long-Horizon Search Agents）**

🔗 https://arxiv.org/abs/2605.05191
📅 2026-05-06 | cs.AI

💡 **核心贡献**
提出 **Context-ReAct** 框架，将推理、上下文管理和工具调用统一到单一循环，定义 5 个原子记忆操作（Skip / Compress / Rollback / Snippet / Delete），动态重塑工作上下文以维持不同粒度的任务相关轨迹。

🔧 **技术亮点**
- 5 个原子操作将记忆管理从"静态追加"升级为"精细可控的动态操作集"
- Rollback 机制允许 Agent 在推理陷入死胡同时恢复到先前状态
- Compress + Snippet 协同实现高信息密度的上下文窗口维护

📊 **实验结果**
在 BrowseComp 基准上达到 **61.5%**，显著优于 Tongyi DeepResearch（43.2%）和 AgentFold（36.2%）。

🎯 **与 Agent/Routing 的关联**
上下文管理策略本质上是一种"信息路由"——在记忆层决定哪些轨迹被保留、压缩或丢弃，直接影响 Agent 长时程推理的质量和效率。

### 3. MEM1：学习协同记忆与推理以实现高效长时程 Agent
**（MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents）**

🔗 https://openreview.net/forum?id=XY8AaxDSLb
📅 ICLR 2026 | 关键词：deep research, reasoning, context compression

💡 **核心贡献**
提出端到端强化学习框架 MEM1，使 Agent 以**近乎恒定的上下文大小**解决长时程任务。每轮交互，MEM1 更新紧凑共享内部状态，同时支持记忆整合与推理，通过 RL + 轨迹截断训练主动丢弃冗余信息。

🔧 **技术亮点**
- 不依赖全上下文 prompt，而是训练 Agent 学会"何时遗忘"
- 共享内部状态（Compact Internal State）融合先验记忆与新观察
- RL 训练 + rollout 截断：在推理驱动的记忆整合上可扩展

📊 **实验结果**
MEM1-7B 在 augmented multi-hop QA（每个任务 16 个目标）上对比 Qwen2.5-14B-Instruct：**性能提升 3.5×，内存占用降低 3.7×**；跨内部检索 QA、开放域 web QA、多轮 web 购物三个域均验证泛化能力。

🎯 **与 Agent/Routing 的关联**
通过学习"记忆路由策略"（保留 vs 丢弃）实现常数级上下文，为长时程 Agent 的推理效率提供可扩展的基础设施支撑。

### 4. Route-To-Reason（RTR）：面向 LLM 与推理策略选择的自适应路由
**（Route to Reason: Adaptive Routing for LLM and Reasoning Strategy Selection）**

🔗 https://arxiv.org/abs/2505.19435
📅 WWW 2026 / ACL 2026 | cs.CL

💡 **核心贡献**
提出 RTR 统一路由框架，**同时**动态分配最合适的 LLM 和推理策略，根据任务难度和预算约束构建路由表，在推理时联合选择最优（模型, 策略）配对，实现真正的即插即用。

🔧 **技术亮点**
- 学习专家模型和推理策略的压缩向量表示，支持联合自适应选择
- 构建路由表（Routing Table）：预测所有组合的期望性能和 Token 消耗
- 低成本、高灵活，支持任意黑盒/白盒模型，无需重训练

📊 **实验结果**
在 7 个开源模型 × 4 种推理策略上，RTR 在准确性与计算效率的权衡上**优于所有基线**；比最佳单模型更准确，同时 Token 使用量降低 **60%+**。

🎯 **与 Agent/Routing 的关联**
RTR 是 LLM Routing 领域的代表性工作，将模型选择和推理策略选择统一建模，解决了传统路由方法仅选模型或仅选策略导致的次优问题。

## 🧠 今日洞察

> **1. 记忆即基础设施，路由即架构决策。** 本日四篇论文无一例外都在挑战"一个模型走天下"或"无限上下文"的假设——无论是 Planner Matters 的算力非均衡分配、LongSeeker 的弹性上下文操作、MEM1 的 RL 记忆整合，还是 RTR 的联合路由，本质都是在探索如何在有限预算下做出最优的"资源路由"决策。

> **2. RL 正在成为 Agent 记忆与规划的统一训练范式。** MEM1 用 RL 训练记忆整合、Planner Matters 用轨迹级 RL 优化规划者——端到端 RL 正在取代手工设计的记忆/规划策略，让 Agent 自主学习何时记、何时忘、何时规划。

> **3. 效率与精度的帕累托前沿正在被系统性突破。** RTR 的 token 节省 60%+、MEM1 的 3.7× 内存降低、Planner Matters 的计算集中化，都指向同一个方向：下一代 Agent 基础设施将以"按需计算"为核心设计原则，而非堆砌算力。
