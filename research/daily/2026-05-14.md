## 📄 **规划器才是关键！面向长时程规划的高效非均衡多智能体协作框架**
（Planner Matters! An Efficient and Unbalanced Multi-agent Collaboration Framework for Long-horizon Planning）

🔗 https://arxiv.org/abs/2605.02168

💡 **核心贡献**
提出将 Agent 自动化分解为三个角色（规划器、执行器、记忆管理器），并通过系统性算力分配分析证明规划能力是决定长时程任务性能的主导因素。基于此，提出以规划器为中心的强化学习方法，仅优化规划器，冻结其余组件，实现计算高效的性能提升。

🔧 **技术亮点**
- 三角色模块化分解：planner（高层决策）+ actor（任务执行）+ memory manager（上下文推理）
- 规划器使用轨迹级奖励 + VLM-as-judge 进行强化学习优化，执行器和记忆管理器冻结
- 算力分配实验揭示：执行与记忆管理仅需极少算力，规划器是瓶颈所在

📊 **实验结果**
在网页导航、操作系统控制、工具使用三类基准上均取得稳健提升；集中算力于规划器显著优于均匀分配策略，代码已开源。

🎯 **与 Agent/Routing 的关联**
直接揭示了 Agent 架构中"算力应向哪个模块路由"的问题，为多模块 Agent 的 Routing 策略设计提供了实验依据。

## 📄 **记忆的诅咒：扩展回忆如何侵蚀 LLM Agent 的合作意图**
（The Memory Curse: How Expanded Recall Erodes Cooperative Intent in LLM Agents）

🔗 https://arxiv.org/abs/2605.08060

💡 **核心贡献**
在多智能体社会困境场景中，发现扩展 LLM 上下文窗口（即增加记忆长度）会系统性地降低合作水平，将这一现象命名为"记忆诅咒"。研究揭示根本原因不是记忆长度，而是历史内容触发的推理模式变化——导致 Agent 放弃前向意图规划，转向短视决策。

🔧 **技术亮点**
- 跨 7 个 LLM、4 种博弈、500 轮实验，覆盖 28 种设置，其中 18 种出现合作下降
- 分析 378,000 条推理轨迹，证明崩溃源于前向意图（forward-looking intent）的消蚀
- LoRA 适配器仅在前向意图轨迹上微调，可缓解衰减并零样本迁移到新游戏；记忆净化实验（替换真实历史为合成合作记录）可恢复合作

📊 **实验结果**
18/28 种模型-游戏配置中合作率显著下降；消融 Chain-of-Thought 推理后衰减减轻，表明过度反思反而放大记忆诅咒；LoRA 干预后合作率恢复到接近短记忆水平。

🎯 **与 Agent/Routing 的关联**
对 Agent 记忆模块设计具有直接警示意义：长程记忆内容的质量与选择策略至关重要，应路由到前向意图增强型推理而非原始历史堆积。

## 📄 **TraceFix：用 TLA+ 反例修复多智能体协调协议**
（TraceFix: Repairing Agent Coordination Protocols with TLA+ Counterexamples）

🔗 https://arxiv.org/abs/2605.07935

💡 **核心贡献**
提出验证优先（verification-first）的多智能体协调流水线 TraceFix：将任务描述自动合成为 PlusCal 形式化协调逻辑，利用 TLA+ 模型检查器（TLC）迭代生成反例并修复，直至协议通过形式化验证后再编译为各 Agent 的系统提示，并在运行时执行拓扑监控。

🔧 **技术亮点**
- 将任务描述转换为结构化中间表示（IR），再生成可验证的 PlusCal 协调逻辑
- TLC 迭代修复循环：62.5% 首次验证通过，无任何任务超过 4 次迭代，每次验证耗时 < 60s
- 运行时拓扑监控拒绝偏离协议的协调操作，形成端到端可靠性保障

📊 **实验结果**
48 个任务 × 16 种场景族，100% 达到完整 TLC 验证；3456 次运行对比中，拓扑监控执行达到最高任务完成率（89.4% 平均 / 81.5% 完整）；TLC 验证协议将死锁/活锁从 31.1% 降至 14.1%（故障注入场景下差距最大）。

🎯 **与 Agent/Routing 的关联**
为多 Agent 协调中的通信协议正确性提供了形式化保障路径，可与 Routing 层结合使用，避免路由到错误状态导致的协调失败。

## 📄 **推理不是免费的：LLM-as-a-Judge 的鲁棒自适应低成本路由**
（Reasoning Is Not Free: Robust Adaptive Cost-Efficient Routing for LLM-as-a-Judge）

🔗 https://arxiv.org/abs/2605.10805

💡 **核心贡献**
系统对比推理型与非推理型 LLM 作为自动评判者的效果与成本，发现推理型模型在结构化验证（数学、代码）任务上显著更优，但在简单评估任务上无益甚至有害且成本高昂。提出 RACER 框架，在固定预算下动态路由选择是否启用推理，并提供理论收敛保证（ICML 2026 录用）。

🔧 **技术亮点**
- 将路由决策建模为约束分布鲁棒优化（DRO）问题，以 KL 散度不确定集显式应对分布偏移
- 提出高效原对偶算法，证明最优策略唯一性与线性收敛
- 支持在"reasoning judge"与"non-reasoning judge"之间自适应切换，粒度细化到单次查询

📊 **实验结果**
在分布偏移场景下，RACER 在精度-成本权衡上优于固定策略基线；与全推理模式相比，在相同精度下成本降低显著；被 ICML 2026 接收。

🎯 **与 Agent/Routing 的关联**
直接是 LLM Routing 问题的前沿工作，将"何时使用重模型推理"的路由决策理论化，对 Agent 中的 Judge/Verifier 组件设计具有直接指导价值。
