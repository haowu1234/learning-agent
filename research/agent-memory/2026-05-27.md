## 📄 Paper 1

📄 **[重新思考如何记忆：超越原子事实的终身 LLM Agent 记忆]**（Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory）
🔗 https://arxiv.org/abs/2605.19952

💡 **核心贡献**
现有基于原子事实提取的记忆范式会丢失细粒度对话细节、无法支持跨散点事实的深度推理；本文提出 **TriMem**，维护三种共存的表示粒度（原始对话片段 / 原子事实 / 合成画像），并用 TextGrad 迭代优化提取提示，实现无参数更新的终身记忆演化。

🔧 **技术亮点**
- 三粒度并存架构：原始对话片段（存储保真度）+ 原子事实（检索效率）+ 合成画像（深层推理），分离存储与推理路径
- TextGrad 自动提示优化：以回答质量为反馈信号迭代细化提取/画像提示，自适应不同对话风格
- 无需更新模型参数，适配任意 LLM 骨干；在 LoCoMo 和 PerLTQA 上持续优于强基线

📊 **实验结果**
在 LoCoMo、PerLTQA 两项终身对话基准、多个 LLM 骨干上一致超越强记忆基线。

🧩 **技术分类**
Memory维度：情景记忆 + 语义记忆 + 记忆检索

🔗 **Memory ↔ Context 关联**
TriMem 通过将对话历史压缩为三粒度结构体，直接减少注入 LLM 上下文的 token 量，同时保留深度推理所需的语义连贯性，是记忆压缩与上下文利用效率协同设计的典型范例。

## 📄 Paper 2

📄 **[情节-语义记忆架构支持长时程科学 Agent]**（Episodic-Semantic Memory Architecture for Long-Horizon Scientific Agents）
🔗 https://arxiv.org/abs/2605.17625

💡 **核心贡献**
科学研究 Agent 在长时程迭代分析中面临上下文窗口饱和和二次代价扩展问题；本文提出**双进程记忆架构**，将即时情节需求（固定 10 条消息窗口）与长期整合知识（~3 tokens/消息线性增长）解耦，首次在科研领域建立情节记忆与语义记忆的领域专化整合方案。

🔧 **技术亮点**
- 解耦双进程设计：情节记忆窗口恒定，语义知识库按需增长，彻底规避二次成本缩放
- 领域专化整合：处理科研特有的参数矛盾演化、跨实验阶段多跳推理、精确技术事实保留
- 大规模交叉模型验证：跨 6 个 LLM（OpenAI/Anthropic/Google 三系），共 15,000 条消息、1,440 个查询

📊 **实验结果**
- 全上下文模型在 10,000 条消息后因溢出崩溃；本架构在使用 62% 更少 token（45,434 vs 120,000+）的情况下维持 70-85% 准确率，延迟 1-2 秒
- 成功管理含 14,000+ 科学事实（125k tokens）的超大语义库
- Dual Process 在数值/时间查询上准确率 65-90%；RAG 在历史检索上 60-85%，两者互补

🧩 **技术分类**
Memory维度：情景记忆 + 语义记忆 + 外部存储；Context维度：上下文管理

🔗 **Memory ↔ Context 关联**
通过解耦情节窗口与语义知识库，将无限延伸的对话上下文转化为结构化记忆，使 Agent 的上下文窗口始终保持固定小尺寸，从根本上解决了"长时程 = 长上下文"的伪命题。

## 📄 Paper 3

📄 **[EvolveMem：面向 LLM Agent 的自进化记忆架构（AutoResearch）]**（EvolveMem: Self-Evolving Memory Architecture via AutoResearch for LLM Agents）
🔗 https://arxiv.org/abs/2605.13941

💡 **核心贡献**
现有记忆系统仅进化存储内容而固化检索机制；EvolveMem 将完整检索配置（评分函数、融合策略、答案生成策略）作为结构化动作空间，由 LLM 驱动的诊断模块基于失败日志自主进行 AutoResearch 闭环优化，实现存储知识与检索机制双重协同进化。

🔧 **技术亮点**
- 自进化闭环：诊断模块读取逐问题失败日志 → 定位根因 → 提出配置调整；元分析器自动执行并附带回退/探索保护
- AutoResearch 过程：系统对自身架构进行自主迭代研究循环，发现原始动作空间中不存在的全新配置维度
- 跨基准正迁移：进化出的配置在 LoCoMo 之外的 MemBench 上同样有效，表明捕获的是通用检索原则

📊 **实验结果**
- LoCoMo 上相对最强基线提升 25.7% F1，相对最小基线提升 78.0%
- MemBench 上超越最强基线 18.9%（相对）
- 代码：https://github.com/aiming-lab/SimpleMem

🧩 **技术分类**
Memory维度：记忆检索 + 外部存储

🔗 **Memory ↔ Context 关联**
通过自主优化检索策略，EvolveMem 动态决定从外部记忆库中取回哪些内容注入上下文，实现了记忆检索精度与上下文注入质量的协同提升。

## 📄 Paper 4

📄 **[δ-mem：大语言模型的高效在线记忆]**（δ-mem: Efficient Online Memory for Large Language Models）
🔗 https://arxiv.org/abs/2605.12357

💡 **核心贡献**
简单扩展上下文窗口代价高昂且难以确保有效利用；本文提出 **δ-mem**，用一个 8×8 联想记忆状态矩阵（通过 delta-rule 在线更新）为冻结全注意力骨干增添轻量工作记忆，无需微调或替换骨干即可提升历史信息积累与复用能力。

🔧 **技术亮点**
- 极度轻量：仅 8×8 在线状态矩阵，通过 delta-rule 学习压缩历史信息
- 低秩注意力修正：在生成时用记忆读出值为注意力计算产生低秩残差，与骨干计算深度耦合
- 冻结骨干友好：无需全量微调或骨干替换，对专有/大规模 LLM 实用性极高

📊 **实验结果**
- 平均分相当于冻结骨干的 1.10× 倍、最强非 δ-mem 基线的 1.15× 倍
- 记忆密集基准：MemoryAgentBench 达 1.31×，LoCoMo 达 1.20×
- 通用能力几乎完全保留

🧩 **技术分类**
Memory维度：工作记忆；Context维度：上下文管理

🔗 **Memory ↔ Context 关联**
δ-mem 将无限增长的上下文历史压缩进固定大小的在线状态，以内化记忆替代外扩上下文窗口，直接打通了"记忆压缩"与"上下文效率"之间的连接。

## 📄 Paper 5

📄 **[隐于记忆：LLM Agent 的休眠记忆投毒攻击]**（Hidden in Memory: Sleeper Memory Poisoning in LLM Agents）
🔗 https://arxiv.org/abs/2605.15338

💡 **核心贡献**
具备持久记忆的 LLM 助手面临新型安全威胁：对抗内容可腐化 Agent 的长期记忆并跨会话持续影响未来行为；本文系统定义并研究**休眠记忆投毒**攻击，揭示持久记忆可成为跨多次会话的长期攻击面。

🔧 **技术亮点**
- 延迟攻击向量：通过操纵文档/网页/代码仓库等外部上下文，诱导 Agent 存储捏造记忆，攻击可休眠并在多次后续对话中复苏
- 全链路评估：投毒记忆写入 → 检索触发 → 恶意 agentic 动作，涵盖完整攻击流水线
- 高威胁数据：GPT-5.5 上投毒记忆写入率高达 99.8%，Kimi-K2.6 达 95%；在成功检索中，60-89% 导致攻击者意图的 agentic 动作

📊 **实验结果**
跨多个前沿模型验证（GPT-5.5、Kimi-K2.6 等），86 页详细评估报告（60 张数据表）。

🧩 **技术分类**
Memory维度：外部存储 + 记忆检索（安全视角）

🔗 **Memory ↔ Context 关联**
攻击通过污染记忆存储层，使未来上下文注入了恶意信息，揭示了记忆系统与上下文构建管道之间的安全耦合脆弱性。

## 📄 Paper 6

📄 **[压缩上下文，保留承诺：可验证 LLM 上下文压缩的形式化框架]**（Compress the Context, Keep the Commitments: A Formal Framework for Verifiable LLM Context Compression）
🔗 https://arxiv.org/abs/2605.17304

💡 **核心贡献**
现有上下文管理方法（截断/检索/摘要/压缩）鲜少明确规定哪些语义承诺必须存活及如何度量其保留程度；本文提出 **Context Codec**，一个承诺级上下文压缩形式化框架，将对话状态表示为带类型、源锚定的语义原子，并引入上下文压缩语言（CCL）作为可审计的紧凑渲染格式。

🔧 **技术亮点**
- 语义原子化：将对话状态分解为带规范身份、等价关系、冲突、置信度、风险和证据跨度的有类型原子
- 五关注点分离：提取 / 归一化 / 表示 / 渲染 / 验证，各阶段独立可审计
- CCL 紧凑格式：ASCII 优先，在结构化散文与 JSON 之间取得中间地带——比散文更显式可审计，通常比 JSON 更紧凑，比重度压缩符号风险更低；引入 Critical Atom Recall / Weighted Atom Recall / Commitment Density / 往返可恢复性等新指标

📊 **实验结果**
小规模诊断研究验证 CCL-Core 在结构化散文与 JSON 之间的实用中间地带；提供完整的语义压缩错误分类体系。

🧩 **技术分类**
Context维度：上下文压缩 + 上下文管理

🔗 **Memory ↔ Context 关联**
Context Codec 的语义原子化表示本质上将对话承诺从非结构化上下文提炼为可持久化的记忆单元，为"上下文压缩即记忆外化"提供了形式化基础。

## 🧠 今日洞察

1. **记忆系统正从"存什么"走向"怎么检索"的自主进化阶段**：EvolveMem 的 AutoResearch 范式和 TriMem 的 TextGrad 自动优化，共同标志着记忆架构研究从手工调参转向闭环自优化的重要拐点——记忆系统开始具备元学习能力。

2. **Memory 与 Context 的协同设计已成主流叙事**：δ-mem 用在线状态矩阵替代上下文扩展、双进程架构将长历史转化为结构化记忆库、Context Codec 将上下文压缩形式化为承诺保留问题——三条技术路线殊途同归，都在寻找"以小的固定成本上下文，支撑大的无限时程记忆"的解法。

3. **记忆安全成为不可忽视的新兴维度**：Sleeper Memory Poisoning 论文揭示，持久记忆并非单纯的能力增强——它同时打开了跨会话延迟攻击的后门；随着 Agent 记忆能力快速成熟，记忆完整性验证（如 Context Codec 的形式化框架）与攻击防御将成为 2026 年下半年的研究热点。
