📄 **δ-mem：面向大语言模型的高效在线记忆机制**（δ-mem: Efficient Online Memory for Large Language Models）
🔗 https://arxiv.org/abs/2605.12357
💡 核心贡献：在冻结的全注意力 backbone 上叠加一个仅 8×8 的关联记忆状态矩阵，通过 delta-rule 将历史信息压缩为固定大小的参数化状态，无需微调、无需替换骨干网络，即可持续更新工作记忆。该方案通过低秩修正机制将压缩后的记忆状态直接耦合到注意力计算中，实现"记忆 → 注意力"的隐式影响。
🔧 技术亮点：
- 关联记忆状态矩阵（8×8）通过 delta-rule 在线更新，极致紧凑，固定内存占用
- 读出（readout）机制生成低秩修正向量，无侵入式修改 backbone 的注意力输出
- 无需全量微调：插件化设计，可叠加到任意已部署的全注意力 LLM
📊 实验结果：MemoryAgentBench +31%，LoCoMo +20%，通用能力几乎不受损
🧩 技术分类：Memory维度：工作记忆 / 记忆压缩
🔗 Memory ↔ Context 关联：将上下文历史压缩为参数化状态矩阵，以极低 token 代价向上下文注入记忆信号，是"让上下文承载更多记忆"的硬件级替代方案。

📄 **可执行的 Agent 记忆：GUI 智能体的结构化经验图谱**（Executable Agentic Memory for GUI Agent, EAM）
🔗 https://arxiv.org/abs/2605.12294
💡 核心贡献：将 GUI 操作规划从"自由生成"转变为"结构化知识图谱的检索-执行"范式——记忆不再是文本，而是可直接执行的程序性知识图谱。使用状态感知 DFS 与动作组挖掘（action-group mining）将多步操作压缩为可复用的图节点，结合 Q-function + MCTS 进行值引导检索。
🔧 技术亮点：
- 状态感知 DFS 构建操作经验图谱，支持路径级压缩与子目标复用
- 轻量级 Q-function 引导 MCTS 在知识图谱上做值导向搜索，避免全空间穷举
- "记忆即程序"——检索到的路径可直接执行，不再需要 LLM 二次推理
📊 实验结果：AndroidWorld 上比 UI-TARS-7B 提升最高 19.6%，token 成本降低 6×（vs GPT-4o），平均延迟 2.8s
🧩 技术分类：Memory维度：情景记忆 / 外部存储 / 记忆检索
🔗 Memory ↔ Context 关联：结构化 KG 检索大幅压缩了送入 LLM 的上下文内容（token -6×），将长操作历史转化为紧凑的可执行图节点，是 Memory 直接缩减 Context 负担的典型案例。

📄 **目标导向的 RAG 记忆推理框架：Goal-Mem**（Goal-Oriented Reasoning for RAG-based Memory in Conversational Agentic LLM Systems）
🔗 https://arxiv.org/abs/2605.12213
💡 核心贡献：现有 RAG 记忆系统以用户话语语义相似度检索，缺乏对"中间缺失事实"的推理，Goal-Mem 引入目标导向逆向推理链，将用户话语分解为原子子目标，对每个子目标定向检索记忆，迭代识别缺口，实现多跳与隐式推理。将推理过程形式化为自然语言逻辑系统（Natural Language Logic），融合一阶逻辑的可验证性与自然语言的表达力。
🔧 技术亮点：
- 目标分解（goal decomposition）：将复杂问题拆解为原子子目标序列，逐步满足
- 逆向链式检索（backward chaining）：从目标出发反向推理所需证据，而非从 query 正向展开
- Natural Language Logic：形式化推理步骤，提升可解释性与可验证性
📊 实验结果：在两个数据集上对比 9 个强基线，多跳推理与隐式推断任务显著领先
🧩 技术分类：Memory维度：外部存储 / 记忆检索；Context维度：上下文管理
🔗 Memory ↔ Context 关联：通过目标驱动的精准检索，仅将真正相关的记忆片段注入上下文，避免无关证据污染上下文，实现"精准 Memory → 精简 Context"的协同。

📄 **EvolveMem：LLM Agent 自进化记忆架构**（EvolveMem: Self-Evolving Memory Architecture via AutoResearch for LLM Agents）
🔗 https://arxiv.org/abs/2605.13941
💡 核心贡献：现有记忆系统将检索基础设施固化，EvolveMem 将完整检索配置（评分函数、融合策略、答案生成策略）暴露为结构化动作空间，由 LLM 诊断模块驱动自主优化——实现知识内容与检索机制的双层协同进化（AutoResearch 过程）。带有自动回归（revert-on-regression）和探索停滞（explore-on-stagnation）保护机制，收敛后的配置可跨基准正迁移。
🔧 技术亮点：
- 双层协进化：存储内容 + 检索机制同时迭代优化，打破"检索机制冻结"的惯例
- LLM 诊断模块读取 per-question 失败日志，识别根因并提出针对性配置调整
- AutoResearch 闭环：系统对自身架构进行自主研究，发现原始动作空间中未存在的新配置维度
📊 实验结果：LoCoMo 相对最强基线 +25.7%，相对最小基线 +78.0%；MemBench 相对最强基线 +18.9%；跨基准迁移呈正迁移
🧩 技术分类：Memory维度：语义记忆 / 外部存储 / 记忆检索
🔗 Memory ↔ Context 关联：通过自进化优化检索配置，动态决定哪些记忆内容以何种方式进入上下文，让上下文窗口始终获得最高质量的记忆注入。

📄 **记忆中潜伏的威胁：LLM Agent 的休眠记忆投毒攻击**（Hidden in Memory: Sleeper Memory Poisoning in LLM Agents）
🔗 https://arxiv.org/abs/2605.15338
💡 核心贡献：提出"休眠记忆投毒"（sleeper memory poisoning）攻击范式——攻击者操控外部上下文（文档、网页、代码库），使 Agent 将伪造记忆写入持久化记忆模块，该攻击可保持休眠并在多次未来对话中重新激活，评估覆盖"写入→检索→触发"完整攻击链。揭示了持久化记忆作为长期攻击面的安全隐患。
🔧 技术亮点：
- 延迟攻击向量：注入时无即时危害，触发条件由未来对话上下文决定，难以实时检测
- 全链路评估：poisoned memory 写入率（GPT-5.5 高达 99.8%）、检索率、最终行为操控率（60-89%）
- 跨模型泛化：在 GPT-5.5、Kimi-K2.6 等多模型上验证，揭示主流商用 LLM 普遍脆弱性
📊 实验结果：GPT-5.5 投毒写入率 99.8%，Kimi-K2.6 95%；成功检索后行为操控率 60-89%
🧩 技术分类：Memory维度：外部存储 / 记忆检索（安全视角）
🔗 Memory ↔ Context 关联：攻击正是利用"外部上下文 → 记忆写入 → 未来上下文注入"的链路，揭示 Context→Memory→Context 闭环中的安全盲点。

📄 **压缩上下文，保留承诺：可验证 LLM 上下文压缩形式化框架**（Compress the Context, Keep the Commitments: A Formal Framework for Verifiable LLM Context Compression）
🔗 https://arxiv.org/abs/2605.17304
💡 核心贡献：LLM 上下文不只是 token，而是一组"承诺"（目标、约束、决策、偏好、工具结果、检索证据、安全边界）。提出 Context Codec 框架，将对话状态表示为带类型、有来源的语义原子（semantic atoms），定义 Critical Atom Recall、Weighted Atom Recall、Commitment Density 等度量，以及 Context Compression Language（CCL）紧凑渲染格式，使压缩过程可验证、可审计。
🔧 技术亮点：
- Semantic Atom 表示：每个承诺具有规范身份、等价性、冲突关系、置信度、风险和证据锚点
- 五关注点分离架构：提取→规范化→表示→渲染→验证，使压缩流水线模块化可测
- CCL（Context Compression Language）：介于结构化散文与 JSON 之间的 ASCII 优先紧凑格式，兼顾可读性与压缩率
📊 实验结果：CCL-Core 在诊断研究中占据散文与 JSON 之间的有效中间地带，显式性和可审计性优于散文，通常比 JSON 更紧凑
🧩 技术分类：Context维度：上下文压缩 / 上下文管理
🔗 Memory ↔ Context 关联：将上下文压缩问题重新定义为"语义承诺保持"问题，与 Memory 领域的语义记忆理论高度对应——压缩上下文本质上是将工作记忆提炼为语义记忆。
