### 1. 📄 **FORGE：无需权重更新的自演化 Agent 记忆——基于群体广播**
（FORGE: Self-Evolving Agent Memory With No Weight Updates via Population Broadcast）

🔗 https://arxiv.org/abs/2605.16233

💡 **核心贡献**
提出 FORGE（失败优化反射-毕业-进化）框架，通过群体广播机制让 LLM Agent 从失败轨迹中自主生成可复用的自然语言记忆，无需任何梯度更新。在分阶段协议中，表现最优的 Agent 实例的记忆被广播给整个种群，实现知识的集体进化。

🔧 **技术亮点**
- 将 Reflexion 风格内循环与群体广播外循环结合：内循环将失败轨迹转化为规则(Rules)、示例(Examples)或混合(Mixed)知识，外循环在阶段间传播最优记忆
- 引入"毕业标准"冻结已收敛的 Agent 实例节省计算，消融实验证明广播机制才是性能提升的关键
- 在随机网络防御 POMDP（CybORG CAGE-2）上跨 4 个 LLM 家族（Gemini/Grok/Llama/Qwen）验证，覆盖 12 种模型-表示配置

📊 **实验结果**
相比零样本基线提升 1.7–7.7×，相比 Reflexion 基线提升 29–72%；主要失败率（<−100）降低至约 1%；较弱基线模型受益更大，表明 FORGE 能弥合能力差距

🧩 **技术分类**
- Memory 维度：情景记忆 / 外部存储 / 记忆检索
- Context 维度：上下文管理

🔗 **Memory ↔ Context 关联**
FORGE 将反思后的失败经验压缩为自然语言知识单元注入 prompt，实现了从交互上下文到持久记忆的高效蒸馏。

### 2. 📄 **xMemory：超越 RAG 的 Agent 记忆——解耦与聚合检索**
（Beyond RAG for Agent Memory: Retrieval by Decoupling and Aggregation）

🔗 https://arxiv.org/abs/2602.02007

💡 **核心贡献**
指出标准 RAG 的 top-k 相似度检索在 Agent 记忆场景中天然失配——Agent 记忆是高度相关的有界对话流而非异构语料库，直接检索会带来冗余与前提丢失。提出 xMemory：先将交互历史解耦为语义组件，再通过稀疏-语义目标聚合为层次结构，自顶向下检索。

🔧 **技术亮点**
- 四层层次结构：原始消息 → 片段(segment) → 记忆组件(memory component) → 组(group)，通过稀疏-语义保真度目标驱动记忆分裂与合并
- 推理时先选取互补的 group/component 骨架，仅在不确定度减少时才向下展开至原始消息，大幅提升 token 效率
- 增量维护记忆结构，支持记忆随对话演化动态更新

📊 **实验结果**
在 LoCoMo 和 PerLTQA 基准上跨多个开/闭源 LLM 取得一致的答案质量提升，并在冗余度、证据密度和覆盖率上均有量化改进

🧩 **技术分类**
- Memory 维度：情景记忆 / 语义记忆 / 记忆检索 / 外部存储

🔗 **Memory ↔ Context 关联**
通过层次解耦将密集对话历史压缩为精简骨架，只在必要时扩展回原始上下文，直接解决 Context 窗口冗余问题。

### 3. 📄 **LME-V2：面向「资深同事」的 Agent 长期记忆评测**
（Evaluating Long-Term Agent Memory Toward Experienced Colleagues）

🔗 https://arxiv.org/abs/2605.12493

💡 **核心贡献**
提出 LongMemEval-V2（LME-V2），首个专门评估 Agent 在定制化 Web 环境中内化经验的长期记忆基准，涵盖 451 道人工精标题目，要求记忆系统从多达 500 条轨迹、1.15 亿 token 的历史中提取紧凑证据。

🔧 **技术亮点**
- 定义五大核心记忆能力：静态状态回忆、动态状态追踪、工作流知识、环境陷阱(gotchas)、前提意识
- 提出 AgentRunbook-R（RAG 式记忆，含原始观测/事件/策略笔记知识池）和 AgentRunbook-C（将轨迹存为文件，由编码 Agent 在沙箱中检索证据）两套方法
- 采用"上下文收集公式"：记忆系统消费历史轨迹，输出下游问答所需的紧凑证据片段

📊 **实验结果**
AgentRunbook-C 达到 72.5% 平均准确率，超越最强 RAG 基线（48.5%）和现成编码 Agent（69.3%），但高准确率伴随高延迟，指出精度-延迟 Pareto 前沿仍有改进空间

🧩 **技术分类**
- Memory 维度：情景记忆 / 工作记忆 / 记忆检索 / 外部存储

🔗 **Memory ↔ Context 关联**
LME-V2 将超长历史轨迹（1.15 亿 token）压缩为紧凑证据窗口，直接体现 Memory 检索对 Context 窗口的剪裁作用。

### 4. 📄 **LLM Agent 记忆机制演化综述：从存储到经验**
（From Storage to Experience: A Survey on the Evolution of LLM Agent Memory Mechanisms）

🔗 https://arxiv.org/abs/2605.06716

💡 **核心贡献**
提出 LLM Agent 记忆机制的统一演化框架，将发展历程形式化为三阶段：存储(Storage)→反思(Reflection)→经验(Experience)，弥合操作系统工程与认知科学两大研究分支，被 ACL 2026 Findings 收录。

🔧 **技术亮点**
- 三阶段框架：存储（轨迹保留）→反思（轨迹精炼）→经验（轨迹抽象），对应不同技术路线的演进脉络
- 剖析三大驱动力：长程一致性需求、动态环境挑战、持续学习目标，为设计选择提供理论指导
- 重点分析前沿"经验"阶段的两大变革机制：主动探索(proactive exploration)与跨轨迹抽象(cross-trajectory abstraction)

🧩 **技术分类**
- Memory 维度：情景记忆 / 语义记忆 / 外部存储 / 记忆检索

🔗 **Memory ↔ Context 关联**
跨轨迹抽象机制将多次交互历史提炼为精简经验表示，减少未来上下文填充压力，是 Memory 与 Context 协同设计的核心命题。

### 5. 📄 **Focus：LLM Agent 的主动上下文压缩与自主记忆管理**
（Active Context Compression: Autonomous Memory Management in LLM Agents）

🔗 https://arxiv.org/abs/2601.07190

💡 **核心贡献**
提出 Focus Agent——一种受生物黏菌(Physarum polycephalum)探索策略启发的 Agent 架构，让 Agent 自主决策何时将关键学习内容固化为持久"知识"块并主动剪枝原始交互历史，而非依赖被动外部摘要。

🔧 **技术亮点**
- Agent 自主控制两种操作：consolidate（将关键学习写入持久知识块）和 withdraw（剪除冗余原始历史）
- 激进 prompt 驱动频繁压缩，平均每任务执行 6.0 次自主压缩，单实例最高节省 57% token
- 使用 Claude Haiku 4.5 在 SWE-bench Lite 上验证，维持 60% 任务准确率的同时降低 22.7% token 用量

📊 **实验结果**
Token 使用量从 14.9M 降至 11.5M（−22.7%），任务准确率 3/5=60% 保持不变；证明强模型在适当工具与 prompt 支持下可自主自律管理上下文

🧩 **技术分类**
- Memory 维度：工作记忆 / 外部存储
- Context 维度：上下文压缩 / 上下文管理

🔗 **Memory ↔ Context 关联**
Focus 将"何时将工作记忆固化为持久外部记忆"与"何时清空上下文窗口"合并为统一 Agent 决策，是 Memory-Context 协同设计的典型实现。

### 6. 📄 **ACON：面向长时程 LLM Agent 的上下文压缩优化**
（ACON: Optimizing Context Compression for Long-horizon LLM Agents）

🔗 https://arxiv.org/abs/2510.00615

💡 **核心贡献**
提出 ACON（Agent Context Optimization）统一框架，同时压缩环境观测和交互历史，通过自然语言空间的压缩准则优化(compression guideline optimization)实现可迁移的压缩策略。

🔧 **技术亮点**
- 成对轨迹分析：给定"完整上下文成功/压缩上下文失败"的轨迹对，用强 LLM 分析失败原因并迭代更新压缩准则
- 将优化后的 LLM 压缩器蒸馏为小模型，降低额外模块开销，蒸馏后保留 >95% 准确率
- 在 AppWorld、OfficeBench 和 Multi-objective QA 三个长时程基准上验证

📊 **实验结果**
峰值 token 使用降低 26–54%，任务性能基本保持；小型 LM 作为长时程 Agent 的性能提升高达 46%

🧩 **技术分类**
- Context 维度：上下文压缩 / 上下文管理
- Memory 维度：工作记忆 / 记忆检索

🔗 **Memory ↔ Context 关联**
ACON 将交互历史（外部记忆流）压缩后重新注入上下文，实现了记忆存储策略与上下文窗口利用率的联合优化。

## 🧠 今日洞察

**① Memory 系统正从被动检索迈向主动进化：** FORGE 的群体广播、xMemory 的层次解耦、Focus 的自主压缩，共同指向同一趋势——下一代 Agent 记忆将具备自我组织与自我精炼能力，而非静态向量存储。

**② 长期记忆的评测标准化成为当务之急：** LME-V2 的出现标志着领域进入系统化评测阶段——115M token 历史规模、五维能力拆分、精度-延迟 Pareto 分析，为记忆系统提供了可比较的竞争基准。

**③ Memory 与 Context 的协同压缩是近期最核心的工程交汇点：** ACON 和 Focus 均证明，仅依靠扩展 Context 窗口并不足够，需要在 Agent 决策层面统一管理"什么值得记住（Memory）"和"什么值得保留在当前窗口（Context）"——这一协同设计正在从论文走向工程实践。
