### 1. LongSeeker：面向长时程搜索 Agent 的弹性上下文编排
**（LongSeeker: Elastic Context Orchestration for Long-Horizon Search Agents）**
🔗 https://arxiv.org/abs/2605.05191
📅 2026-05-06 | 作者：Rui Ye, Yuwen Du, Jiajun Wang 等

💡 **核心贡献**
提出 Context-ReAct 框架，将推理、上下文管理与工具调用统一到一个循环中，引入五个原子操作（Skip / Compress / Rollback / Snippet / Delete）对工作记忆进行弹性重塑。在此基础上微调得到 LongSeeker，BrowseComp 上达到 61.5%，显著超越 Tongyi DeepResearch（43.2%）和 AgentFold（36.2%）。

🔧 **技术亮点**
- 五原子操作：Compress（压缩已解决信息）、Snippet（保留关键证据片段）、Rollback（回滚至先前状态）、Skip（跳过无关内容）、Delete（删除冗余分支），粒度远超现有"追加/摘要"两态模式
- 证明 Compress 算子的表达完备性，其他专用算子提供效率与保真度保证，可降低幻觉风险
- 在 Qwen3-30B-A3B 上合成 10k 轨迹微调，BrowseComp-ZH 达 62.5%

📊 **实验结果**
BrowseComp：61.5%（vs Tongyi DeepResearch 43.2%，+18.3pp）；BrowseComp-ZH：62.5%（vs AgentFold 47.3%，+15.2pp）

🧩 **技术分类**
- Memory 维度：工作记忆 / 记忆压缩 / 记忆检索
- Context 维度：上下文压缩 / 上下文管理

🔗 **Memory ↔ Context 关联**
该工作将工作记忆的动态管理与上下文窗口压缩深度融合，通过原子操作直接在上下文层面实现记忆的写入、压缩与回溯，是 Memory-as-Context 理念的最新实践。

### 2. MEMTIER：面向长期运行自主 Agent 的分层记忆架构与检索瓶颈分析
**（MEMTIER: Tiered Memory Architecture and Retrieval Bottleneck Analysis for Long-Running Autonomous AI Agents）**
🔗 https://arxiv.org/abs/2605.03675
📅 2026-05-05 | 作者：Bronislav Sidik 等

💡 **核心贡献**
识别现有平面文件记忆系统在 72 小时长期运行中存在四类复合失效模式，提出 MEMTIER 三层记忆架构（情节层 → 语义层 → 工作层），通过五信号加权检索引擎与 PPO 策略框架自适应调节检索权重。在消费级 6GB GPU 上，LongMemEval-S 准确率从 5% 提升至 38.2%（+33pp）。

🔧 **技术亮点**
- 三层架构：结构化情节 JSONL 存储 + 异步巩固守护进程（将情节事实提升至语义层）+ 注意力归因认知权重更新循环
- 五信号加权检索：超越单一向量相似度，融合时间衰减、语义相关性、使用频率等多维信号
- 全程在消费级笔记本（6GB GPU）上本地运行，具备边缘部署可行性

📊 **实验结果**
LongMemEval-S（500 题）：Acc=0.382，F1=0.412（Qwen2.5-7B），较全上下文基线（0.050）提升 33pp；配合 DeepSeek-V4-Flash 预填充，单 Session 召回率达 0.686–0.714，超越 RAG BM25 + GPT-4o 基线（0.560）

🧩 **技术分类**
- Memory 维度：情景记忆 / 语义记忆 / 外部存储 / 记忆检索
- Context 维度：上下文管理

🔗 **Memory ↔ Context 关联**
通过异步巩固机制将情节记忆中的高价值内容蒸馏为语义记忆，再按需注入上下文窗口，实现了记忆与上下文容量的解耦与协同管理。

### 3. Experience-RAG Skill：面向 Agent 的可插拔经验驱动检索策略编排
**（An Agent-Oriented Pluggable Experience-RAG Skill for Experience-Driven Retrieval Strategy Orchestration）**
🔗 https://arxiv.org/abs/2605.03989
📅 2026-05-05（v2: 2026-05-07）| 作者：Dutao Zhang 等

💡 **核心贡献**
打破"一条检索管道适配所有任务"的假设，提出 Experience-RAG Skill——一个位于 Agent 与检索池之间的可插拔编排层，通过维护经验记忆（experience memory）动态选择最优检索策略，在 BeIR 多任务基准上 nDCG@10 达 0.8924。

🔧 **技术亮点**
- 将检索策略选择封装为可复用的 Agent Skill，与上层工作流解耦，实现即插即用
- 经验记忆驱动：分析当前场景并查阅历史经验，自适应路由到最优检索器（factoid QA / multi-hop / scientific verification）
- 在固定候选池下与 Adaptive-RAG 风格路由保持竞争力，无需额外训练检索器

📊 **实验结果**
BeIR/nq + BeIR/hotpotqa + BeIR/scifact 综合 nDCG@10：0.8924，优于固定单检索器基线

🧩 **技术分类**
- Memory 维度：外部存储 / 记忆检索 / 情景记忆（经验积累）
- Context 维度：上下文管理 / In-Context 学习

🔗 **Memory ↔ Context 关联**
经验记忆不直接进入上下文，而是通过策略路由控制注入上下文的证据质量与密度，体现了记忆在上下文管理中的"元调度"作用。

### 4. ScrapMem：基于光学遗忘的仿生端侧个性化 Agent 记忆框架
**（ScrapMem: A Bio-inspired Framework for On-device Personalized Agent Memory via Optical Forgetting）**
🔗 https://arxiv.org/abs/2605.03804
📅 2026-05-05 | 作者：Jiale Chang 等

💡 **核心贡献**
针对边缘设备的存储与多模态复杂性挑战，提出仿生 ScrapMem 框架，引入光学遗忘（Optical Forgetting）机制——对旧记忆渐进式降分辨率压缩，存储减少 93%，同时构建情节记忆图（EM-Graph）维护因果时序结构，ATM-Bench 上 Joint@10 达 51.0% SOTA。

🔧 **技术亮点**
- 光学遗忘：模拟人类记忆衰退，渐进降低旧记忆分辨率，低价值细节自动抹除，存储节省 93%
- EM-Graph：将关键事件组织为因果时序结构，保障语义一致性与时序可推理性
- 多模态一体化：将文本、图像等多模态数据融合至"Scrapbook Page"统一存储单元

📊 **实验结果**
ATM-Bench：Joint@10 = 51.0%（SOTA）；Recall@10 = 70.3%（通过结构化聚合提升）；存储节省 93%

🧩 **技术分类**
- Memory 维度：情景记忆 / 外部存储 / 记忆压缩
- Context 维度：上下文压缩

🔗 **Memory ↔ Context 关联**
光学遗忘通过压缩旧记忆内容降低上下文注入时的噪声，EM-Graph 则为检索时的上下文重建提供结构化导航，形成"存储压缩 → 结构化检索 → 上下文注入"的完整链路。

### 5. MemMachine：保真地面真相的个性化 Agent 长期记忆系统
**（MemMachine: A Ground-Truth-Preserving Memory System for Personalized AI Agents）**
🔗 https://arxiv.org/abs/2604.04853
📅 2026-04 | 作者：（开源项目）

💡 **核心贡献**
针对多 Session 交互中 RAG 管道精度衰减问题，提出开源 MemMachine，整合短期、长期情节与画像记忆于"地面真相保真架构"（存储完整会话，减少有损 LLM 抽取），配合伴生检索 Agent 自适应路由，在 LongMemEvalS 上达 93.0% 准确率。

🔧 **技术亮点**
- 地面真相保真：存储完整对话情节而非 LLM 提炼摘要，从源头降低信息损失
- 上下文化检索（contextualized retrieval）：将 nucleus 命中结果扩展为周边对话轮次，提升跨轮次证据的召回率
- 伴生检索 Agent：自适应路由于直接检索 / 并行分解 / 迭代链式查询三种策略

📊 **实验结果**
LoCoMo：0.9169（gpt4.1-mini）；LongMemEvalS：93.0%；vs Mem0：输入 token 减少约 80%；HotpotQA-hard：93.2%；WikiMultiHop：92.6%（随机噪声条件）

🧩 **技术分类**
- Memory 维度：情景记忆 / 语义记忆 / 外部存储 / 记忆检索
- Context 维度：上下文管理

🔗 **Memory ↔ Context 关联**
通过保留完整情节降低上下文摘要的信息熵损耗，同时通过上下文化检索精确控制注入上下文的证据粒度，实现了"高保真存储 + 精准上下文填充"的协同。

### 6. 上下文注入的交叉效应：多 Agent 设计探索中知识迁移的双面性
**（When Context Hurts: The Crossover Effect of Knowledge Transfer on Multi-Agent Design Exploration）**
🔗 https://arxiv.org/abs/2605.04361
📅 2026-05-05 | 作者：Saranyan Vigraham

💡 **核心贡献**
基于 2,700 次多 Agent 软件设计实验，首次系统揭示上下文注入的"交叉效应"：相同知识制品在某些任务上提升探索效率（最高 20×），在其他任务上反而降低效率（最高 46%），并发现基线探索能力是唯一可测量的预测变量（Pearson r = −0.82）。

🔧 **技术亮点**
- 交叉效应的定量刻画：在 10 个任务 × 7 种上下文注入条件下，系统测量"上下文伤害"的可复现性
- 两类收敛机制区分：训练数据先验驱动的"自然收敛" vs 显式指令驱动的"诱导收敛"，对上下文干预的响应截然不同
- 廉价诊断协议：一次无上下文试验即可预测上下文注入是否有益，改变 RAG 系统的使用范式

📊 **实验结果**
10 任务 × 7 条件 × 400 次 run 共 2,700+ 实验；基线探索能力预测方向性 Pearson r = −0.82（p < 0.001）；上下文加速最高 20×，减速最高 46%

🧩 **技术分类**
- Memory 维度：记忆检索（选择性）/ 外部存储
- Context 维度：上下文管理 / In-Context 学习

🔗 **Memory ↔ Context 关联**
揭示记忆注入上下文并非总是有益，提示 Memory-Context 协同需引入任务感知的条件性检索机制，而非无条件全量注入。

## 🧠 今日洞察

1. **记忆操作正在原语化**：以 LongSeeker 的五原子操作为代表，Agent Memory 管理正从"读写两态"演进为具备丰富语义的操作集合（Compress / Rollback / Snippet），这标志着上下文管理从被动响应转向主动编排，Memory 与 Context 的边界进一步模糊。

2. **分层架构成为长期记忆主流范式**：MEMTIER、MemMachine、ScrapMem 三篇工作不约而同地采用多层记忆结构（工作记忆 → 情节记忆 → 语义记忆），并配合异步巩固机制实现层间流转，表明"扁平 RAG"正被"分层记忆系统"系统性取代，同时大幅压缩对上下文窗口的依赖。

3. **"更多上下文 = 更好"的假设正在被动摇**：When Context Hurts 与 Experience-RAG Skill 共同揭示了上下文注入的选择性与条件性——记忆的价值不在于数量而在于策略性注入，Memory ↔ Context 协同设计的核心命题正从"如何存储更多"转向"何时注入什么、如何验证效益"。
