### Paper 1

📄 **[MemPrivacy：边云协同 Agent 的隐私保护个性化记忆管理]**（MemPrivacy: Privacy-Preserving Personalized Memory Management for Edge-Cloud Agents）
🔗 https://arxiv.org/abs/2605.09530

💡 **核心贡献**
提出 MemPrivacy 框架，在边缘侧识别隐私敏感片段并替换为语义结构化的类型感知占位符，再由云端完成记忆处理，本地恢复原始值，实现隐私保护与记忆效用的双赢。该方案解耦了隐私保护与语义破坏，让 Agent 的个性化记忆在云辅助环境下既安全又实用。

🔧 **技术亮点**
- 边缘侧隐私识别 + 语义占位符替换策略，云端不接触原始敏感数据
- 构建 MemPrivacy-Bench：覆盖 200 用户、5.2 万+ 隐私实例的评测数据集，含四级隐私分类体系
- 与 GPT-5.2、Gemini-3.1-Pro 等强模型相比，隐私信息提取性能显著更优，同时降低推理延迟

📊 **实验结果**
在多个主流记忆系统上，MemPrivacy 将效用损失控制在 1.6% 以内，大幅超越基线掩码策略。

🧩 **技术分类**
Memory维度：外部存储 / 记忆检索（个性化长期记忆）

🔗 **Memory ↔ Context 关联**
通过在 Context 传入云端之前对隐私 span 进行精准替换，本质是在记忆写入路径上注入了隐私感知的上下文净化层。

### Paper 2

📄 **[DeepRefine：基于强化学习的 Agent 知识库精炼]**（DeepRefine: Agent-Compiled Knowledge Refinement via Reinforcement Learning）
🔗 https://arxiv.org/abs/2605.10488

💡 **核心贡献**
提出 DeepRefine，一个通用 LLM 推理模型，通过多轮交互与知识库进行溯因诊断，定位不完整、错误、冗余等缺陷并执行增量修复，持续提升 Agent 外部知识库的质量。引入无需黄金参考的 Gain-Beyond-Draft (GBD) 奖励，端到端强化学习优化精炼策略。

🔧 **技术亮点**
- 多轮交互 + 溯因诊断（Abductive Diagnosis）：对交互历史进行缺陷定位，执行靶向修复动作
- GBD 奖励函数：无需人工标注金标准，通过"精炼后增益超过草稿基线"来量化改进
- 支持跨文档链接修复、指代消解、低置信度断言精炼等细粒度知识缺陷修复

📊 **实验结果**
在多个知识密集型下游任务上一致超越强基线，证明知识库质量提升可有效传导到任务性能增益。

🧩 **技术分类**
Memory维度：外部存储 / 语义记忆（知识库质量持续优化）

🔗 **Memory ↔ Context 关联**
知识库精炼直接改善了 RAG 管线中检索到的上下文质量，减少噪声上下文对 LLM 推理的干扰。

### Paper 3

📄 **[RubricEM：基于评分准则的 Agent 记忆蒸馏与元策略强化学习]**（RubricEM: Meta-RL with Rubric-guided Policy Decomposition beyond Verifiable Rewards）
🔗 https://arxiv.org/abs/2605.10899

💡 **核心贡献**
提出 RubricEM，将评分准则（Rubric）作为 Agent 策略执行、评判反馈与记忆的统一接口，通过阶段感知的策略分解和反思式元策略演化，让 Agent 将历史轨迹蒸馏为可复用的 Rubric 导向经验指导。解决了深度研究 Agent 在无可验证奖励场景下的长程强化学习难题。

🔧 **技术亮点**
- Stage-Structured GRPO：阶段感知的策略分组优化，基于 Rubric 阶段性判断提供稠密语义反馈
- 反思元策略（Reflection Meta-Policy）：共享骨干网络将过去轨迹蒸馏为可复用的 Rubric 指导，实现经验记忆的结构化存储
- 将研究轨迹分解为规划、证据收集、审查、合成四个阶段，每阶段条件化于自生成 Rubric

📊 **实验结果**
RubricEM-8B 在四个长篇研究基准上超越同规模开源模型，接近商业深度研究系统性能。

🧩 **技术分类**
Memory维度：情景记忆 / 工作记忆（轨迹蒸馏为可复用经验）

🔗 **Memory ↔ Context 关联**
Rubric 充当结构化上下文锚点，将长程轨迹的语义信息压缩后注入未来 Agent 决策的上下文，实现情景记忆向上下文指导的转化。

### Paper 4

📄 **[LongSeeker：面向长程搜索 Agent 的弹性上下文编排]**（LongSeeker: Elastic Context Orchestration for Long-Horizon Search Agents）
🔗 https://arxiv.org/abs/2605.05191

💡 **核心贡献**
提出 Context-ReAct 范式，将推理、上下文管理与工具调用统一到一个循环中，并设计五种原子操作（Skip、Compress、Rollback、Snippet、Delete）让 Agent 动态重塑工作上下文。基于此范式微调 LongSeeker，在 BrowseComp 等基准上取得 SOTA。

🔧 **技术亮点**
- 五原子操作的弹性上下文编排：可保留关键证据、压缩已解决信息、丢弃无用分支
- 理论证明 Compress 操作具备表达完备性，其余操作提供效率与保真度保证
- 基于 Qwen3-30B-A3B 在 1 万条合成轨迹上微调，轻量化训练实现高性能

📊 **实验结果**
BrowseComp: 61.5%（vs. Tongyi DeepResearch 43.2%，AgentFold 36.2%）；BrowseComp-ZH: 62.5%（vs. 46.7% / 47.3%）。

🧩 **技术分类**
Context维度：上下文压缩 / 上下文管理（工作记忆动态重塑）

🔗 **Memory ↔ Context 关联**
弹性上下文操作本质是对 Agent 工作记忆的主动管理，Compress 操作将情景信息压缩进上下文，Rollback 则实现了类似记忆回溯的机制。

### Paper 5

📄 **[Focus：LLM Agent 的自主上下文压缩架构]**（Active Context Compression: Autonomous Memory Management in LLM Agents）
🔗 https://arxiv.org/abs/2601.07190

💡 **核心贡献**
提出 Focus Agent，受黏菌生物探索策略启发，让 Agent 自主决策何时将关键学习内容整合到持久"知识块"（Knowledge block）并主动修剪原始交互历史，解决长程软件工程任务中的"上下文膨胀"问题。

🔧 **技术亮点**
- Agent 自主触发压缩：无需外部干预，模型自主判断压缩时机和内容
- 知识块持久化：将关键学习内容写入结构化持久存储，区别于简单摘要
- 平均每任务执行 6.0 次自主压缩，单任务最高节省 57% Token

📊 **实验结果**
SWE-bench Lite（N=5实例）：22.7% Token 缩减（14.9M→11.5M），准确率保持不变（3/5 = 60%）。

🧩 **技术分类**
Context维度：上下文压缩 / 上下文管理；Memory维度：工作记忆

🔗 **Memory ↔ Context 关联**
知识块充当短期工作记忆到长期记忆的桥梁，通过主动修剪历史上下文来为新的工作记忆腾出空间。

### Paper 6

📄 **[记忆诅咒：扩展回溯如何侵蚀 LLM Agent 的合作意图]**（The Memory Curse: How Expanded Recall Erodes Cooperative Intent in LLM Agents）
🔗 https://arxiv.org/abs/2605.08060

💡 **核心贡献**
发现并系统研究"记忆诅咒"现象：在多 Agent 社会博弈中，扩大历史上下文窗口反而系统性地降低合作率（7个LLM × 4个博弈 × 500轮，28个模型-游戏组合中18个出现衰退）。揭示根本机制是长回溯侵蚀了前瞻性意图，而非偏执加剧。

🔧 **技术亮点**
- 词汇分析 37.8 万条推理链，定量关联合作崩溃与前瞻意图减少
- 记忆净化实验（Memory Sanitization）：保持上下文长度不变但替换为合成合作记录，合作率大幅恢复，证明触发因素是记忆内容而非长度
- LoRA 适配器认知探针：在前瞻推理链上微调后可迁移零样本缓解其他游戏中的记忆诅咒

🧩 **技术分类**
Memory维度：情景记忆（历史回溯副作用）；Context维度：长窗口扩展（负向效应研究）

🔗 **Memory ↔ Context 关联**
揭示了上下文窗口扩展与情景记忆内容之间的关键张力：更长的上下文不等于更好的记忆，记忆内容的质量与推理模式共同决定上下文扩展的效果。

## 🧠 今日洞察

1. **Memory 主动管理成为主流范式**：从 Focus 的自主压缩到 LongSeeker 的弹性上下文编排，再到 RubricEM 的轨迹蒸馏，Agent 正从被动接受上下文转向主动管理工作记忆，"何时压缩、何时保留、何时遗忘"成为 Agent 能力的核心维度。

2. **知识库质量闭环正在形成**：DeepRefine 的 RL 驱动知识精炼 + MemPrivacy 的隐私保护记忆管理，共同指向一个趋势：外部记忆不再是静态仓库，而是需要持续维护的活知识体，Agent 自身负责检测与修复记忆缺陷。

3. **Memory × Context 协同设计出现"反向警示"**：《记忆诅咒》论文揭示了盲目扩大上下文/回溯范围的潜在危害——在多 Agent 协作场景中，记忆内容的质量与推理模式必须协同设计，这为 Memory-Context 联合优化框架提出了新的约束条件，预示着未来的研究将更关注"选择性记忆"而非"全量记忆"。
