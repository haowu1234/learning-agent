📄 **LatentRAG：基于潜空间推理与检索的高效 Agentic RAG**（LatentRAG: Latent Reasoning and Retrieval for Efficient Agentic RAG）
🔗 https://arxiv.org/abs/2605.06285
💡 核心贡献：提出将 Agentic RAG 的推理与检索过程从离散语言空间迁移至连续潜空间，通过单次前向传播生成潜在 token 完成子查询，从而大幅降低推理延迟；引入并行潜空间解码机制保证语义可解释性，实现端到端联合优化。
🔧 技术亮点：
  - 直接从隐藏状态生成潜在子查询 token，无需自回归逐 token 生成
  - LLM 与稠密检索模型在潜空间对齐，支持潜空间 token 直接驱动检索
  - 并行潜空间解码：将潜 token 反译为自然语言，提升透明度
📊 实验结果：在7个基准数据集上性能与显式 Agentic RAG 相当，推理延迟降低约 **90%**，大幅缩小与传统单步 RAG 的速度差距
🧩 技术分类：Memory维度：记忆检索；Context维度：上下文压缩 / In-Context学习
🔗 Memory ↔ Context 关联：将外部检索记忆的查询生成压缩至潜空间，用连续表示替代显式上下文，实现记忆检索与上下文生成的统一优化。

📄 **xMemory：超越 RAG 的 Agent 记忆——解耦与聚合式检索**（Beyond RAG for Agent Memory: Retrieval by Decoupling and Aggregation）
🔗 https://arxiv.org/abs/2602.02007
💡 核心贡献：指出 Agent 记忆场景与 RAG 假设不匹配（有界对话流 vs. 大规模异质语料），提出 xMemory，通过将记忆解耦为语义组件并构建层次结构来驱动检索，有效避免冗余和误删前提链路。
🔧 技术亮点：
  - 稀疏-语义目标（sparsity–semantics objective）驱动记忆的分裂与合并，维护可搜索的高层节点组织
  - 自顶向下检索：先选取紧凑多样的主题/语义，再按需展开至情节和原始消息
  - 不确定性驱动扩展：仅当展开能降低 reader 不确定性时才下沉到原始对话片段
📊 实验结果：在 LoCoMo 和 PerLTQA 基准（三款最新 LLM）上，答案质量和 token 效率均有持续提升
🧩 技术分类：Memory维度：情景记忆 / 语义记忆 / 记忆检索；Context维度：上下文管理
🔗 Memory ↔ Context 关联：层次记忆结构使得检索时仅将必要上下文加载入窗口，直接控制上下文大小与质量的平衡。

📄 **MemMachine：面向个性化 AI Agent 的真值保全记忆系统**（MemMachine: A Ground-Truth-Preserving Memory System for Personalized AI Agents）
🔗 https://arxiv.org/abs/2604.04853
💡 核心贡献：提出 MemMachine，整合短期记忆、长期情景记忆与档案记忆，采用真值保全架构（存储完整对话片段而非 LLM 提取摘要），配合自适应检索 Agent 实现多策略路由。
🔧 技术亮点：
  - 上下文化检索：以核心匹配为锚点，扩展包含周边对话轮次，提升多轮证据召回率
  - 检索阶段四项优化：深度调优(+4.2%)、格式化(+2.0%)、搜索提示设计(+1.8%)、查询偏差修正(+1.4%)
  - Retrieval Agent 自适应路由：直接检索 / 并行分解 / 迭代链式查询三策略动态选择
📊 实验结果：LoCoMo 基准 0.9169（gpt4.1-mini）；LongMemEvalS 六维消融达 **93.0%** 准确率；HotpotQA-hard 93.2%，WikiMultiHop 92.6%；相比 Mem0 减少约 **80%** 输入 token
🧩 技术分类：Memory维度：情景记忆 / 外部存储 / 记忆检索；Context维度：上下文管理
🔗 Memory ↔ Context 关联：以"存全集"代替"摘要提取"保持原始上下文完整性，通过检索策略路由控制放入上下文的信息量，兼顾真值保全与 token 效率。

📄 **Experience-RAG Skill：面向 Agent 的可插拔经验驱动检索策略编排**（An Agent-Oriented Pluggable Experience-RAG Skill for Experience-Driven Retrieval Strategy Orchestration）
🔗 https://arxiv.org/abs/2605.03989
💡 核心贡献：在 Agent 与检索池之间引入可插拔的"经验记忆层"，根据当前场景查阅经验记忆动态选择最优检索策略，将检索策略选择封装为可复用的 Agent Skill，解耦上层工作流与检索逻辑。
🔧 技术亮点：
  - 场景感知分析：自动识别 factoid QA / multi-hop 推理 / 科学验证等不同检索偏好场景
  - 经验记忆驱动路由：查阅历史执行经验决策最优检索器，而非静态规则
  - 插件化设计：作为独立 Skill 与 Agent 松耦合，可无缝替换底层检索器池
📊 实验结果：在 BeIR/nq、BeIR/hotpotqa、BeIR/scifact 上 nDCG@10 = **0.8924**，优于固定单检索器基线，媲美 Adaptive-RAG 路由
🧩 技术分类：Memory维度：情景记忆 / 记忆检索；Context维度：上下文管理
🔗 Memory ↔ Context 关联：以历史检索经验作为记忆指导当前检索策略选择，使注入上下文的证据质量更高、更具针对性。

📄 **Focus Agent：主动上下文压缩——LLM Agent 自主记忆管理**（Active Context Compression: Autonomous Memory Management in LLM Agents）
🔗 https://arxiv.org/abs/2601.07190
💡 核心贡献：提出 Focus Agent，受黏菌探索策略启发，让 Agent 自主决策何时将关键学习成果固化为持久"知识块"并主动剪枝原始交互历史，解决长周期软件工程任务中的"Context Bloat"问题。
🔧 技术亮点：
  - Agent 自主驱动压缩：无需外部总结器，Agent 内部判断压缩时机并执行
  - 知识块持久化：将核心学习成果写入独立 Knowledge 模块，与原始历史解耦
  - 优化 Scaffold：持久化 bash + 字符串替换编辑器，结合激进压缩提示
📊 实验结果：在 SWE-bench Lite 5个 context-intensive 实例上，token 减少 **22.7%**（14.9M→11.5M），精度保持不变（60%）；单实例最高节省 **57%** token；平均每任务执行 6.0 次自主压缩
🧩 技术分类：Memory维度：工作记忆 / 情景记忆；Context维度：上下文压缩 / 上下文管理
🔗 Memory ↔ Context 关联：将工作记忆中的重要信息主动蒸馏为持久知识块，通过压缩交互历史实现上下文窗口的自主动态管理。

📄 **ACON：面向长周期 LLM Agent 的上下文压缩优化框架**（ACON: Optimizing Context Compression for Long-horizon LLM Agents）
🔗 https://arxiv.org/abs/2510.00615
💡 核心贡献：提出 ACON（Agent Context Optimization）统一框架，将环境观测与交互历史同时压缩为简洁高信息量的凝缩表示，并通过自然语言空间的压缩指南优化和蒸馏小型压缩模型降低额外开销。
🔧 技术亮点：
  - 对比轨迹分析：给定全文成功/压缩失败的轨迹对，驱动 LLM 分析失败原因并更新压缩指南
  - 双路压缩：同时优化环境观测（observation）和交互历史（history）两类上下文
  - 压缩模型蒸馏：将优化后的 LLM 压缩能力蒸馏到小模型，压缩时保留 >95% 精度
📊 实验结果：AppWorld / OfficeBench / Multi-objective QA 上 peak token 减少 **26–54%**，任务性能基本保持；蒸馏后小型 LM 作为长周期 Agent 性能提升最高 **46%**（ICML 2026）
🧩 技术分类：Memory维度：工作记忆 / 外部存储；Context维度：上下文压缩 / 长窗口扩展
🔗 Memory ↔ Context 关联：通过压缩 Agent 历史记忆（交互轨迹）控制上下文增长，以知识蒸馏实现记忆压缩能力的模型化内化。

## 🧠 今日洞察

1. **记忆检索正从相似度匹配走向结构感知与策略感知**：xMemory 的层次解耦检索和 Experience-RAG Skill 的经验驱动路由共同表明，Agent 记忆检索已不满足于 top-k 相似匹配，而转向对记忆内容结构和历史经验的深度利用，以提升精准度和多样性。

2. **上下文压缩进入"自主化"与"端到端"双轨并进时代**：Focus Agent 实现了 Agent 自主驱动的上下文自我管理，而 LatentRAG 则将 RAG 的检索-推理过程整体压缩至潜空间实现端到端联合优化，两条路线从不同维度解决 Context Bloat 的根本矛盾。

3. **Memory 与 Context 协同设计趋势明确**：MemMachine 以"全量存储 + 自适应检索路由"将记忆完整性与上下文 token 效率解耦，ACON 以"压缩指南优化 + 小模型蒸馏"将记忆压缩能力内化为模型参数——两者均指向同一方向：**不再把记忆和上下文视为独立模块，而是设计协同控制机制，实现长期记忆的忠实保存与短期上下文的动态精简的统一**。
