### 1

📄 **δ-mem：面向大语言模型的高效在线记忆机制**（δ-mem: Efficient Online Memory for Large Language Models）
🔗 https://arxiv.org/abs/2605.12357
📅 2026-05-12 | cs.AI

💡 **核心贡献**
在冻结的全注意力 backbone 上增加一个极紧凑（8×8）的关联记忆状态矩阵，通过 delta-rule 在线更新，并以低秩修正方式耦合到注意力计算中，无需任何微调即可显著提升记忆密集型任务的表现。

🔧 **技术亮点**
- 仅 64 个参数（8×8 矩阵）即可捕获过往信息，大幅降低内存和计算开销
- 通过 delta-rule 学习将历史信息压缩为固定大小在线状态，读出后生成低秩注意力修正
- 不替换 backbone，不扩展上下文窗口，作为"外挂模块"即插即用

📊 **实验结果**
- MemoryAgentBench 提升 1.31×，LoCoMo 提升 1.20×
- 平均提升 1.10×（vs 冻结 backbone），1.15×（vs 最强非 δ-mem 基线）
- 通用能力几乎不受影响

🧩 **技术分类**
Memory维度：工作记忆 / 参数化在线状态记忆（Associative Memory）

🔗 **Memory ↔ Context 关联**
δ-mem 将扩展上下文窗口的"空间问题"转化为注意力修正的"压缩问题"，用参数化状态取代上下文长度增长，是 Memory 与 Context 协同设计的精巧范例。

### 2

📄 **EAM：面向 GUI Agent 的可执行代理记忆**（Executable Agentic Memory for GUI Agent）
🔗 https://arxiv.org/abs/2605.12294
📅 2026-05-12 | cs.AI

💡 **核心贡献**
将 GUI 任务规划从自由文本生成转变为"结构化知识图谱检索 + 执行"的范式——操作经验被"编译"为可执行的图结构，并通过 Q-function 引导 MCTS 进行值导向图搜索，实现记忆即策略。

🔧 **技术亮点**
- 状态感知 DFS + 动作组挖掘（action-group mining）构建样本高效记忆知识图谱
- 轻量级 Q-function 模型引导 MCTS 在知识图谱上进行值引导搜索
- 检索到的图路径可直接执行，"记忆 = 可复用程序"而非参考文本

📊 **实验结果**
- AndroidWorld 任务成功率比 UI-TARS-7B 提升最高 19.6%
- Token 成本降低 6×（相对 GPT-4o），平均延迟仅 2.8s

🧩 **技术分类**
Memory维度：情景记忆 / 程序性记忆 / 外部存储（Executable Knowledge Graph）

🔗 **Memory ↔ Context 关联**
EAM 将长交互历史"编译"进知识图谱，彻底消除了重复经历对上下文窗口的占用，以结构化外部记忆替代线性上下文积累。

### 3

📄 **Goal-Mem：基于 RAG 的对话 Agent 目标导向记忆推理框架**（Goal-Mem: Goal-Oriented Reasoning for RAG-based Memory in Conversational Agentic LLM Systems）
🔗 https://arxiv.org/abs/2605.12213
📅 2026-05-12 | cs.AI

💡 **核心贡献**
提出从用户话语出发的逆向链式推理框架——将目标分解为原子子目标后再定向检索，而非基于原始语义相似度检索，并将推理过程形式化为"自然语言逻辑"（FOL 可验证性 + 自然语言表达力），显著改善多跳推理与隐式推断场景下的 RAG 表现。

🔧 **技术亮点**
- 目标驱动的逆向推理链（Backward Chaining）：话语 → 子目标分解 → 定向检索 → 缺口识别 → 迭代
- Natural Language Logic 系统兼顾 FOL 的可验证性与自然语言的表达灵活性
- 在无法满足中间子目标时触发迭代推理，动态补充缺失证据

📊 **实验结果**
- 两个数据集上对比 9 个强基线均取得显著提升，多跳推理和隐式推断任务上领先最明显

🧩 **技术分类**
Memory维度：记忆检索 / 情景记忆；Context维度：上下文管理 / In-Context学习

🔗 **Memory ↔ Context 关联**
Goal-Mem 用推理驱动的选择性检索控制写入上下文的记忆量，有效避免无关记忆污染上下文窗口，实现 Memory 与 Context 的精准协同。

### 4

📄 **MemReranker：面向 Agent 记忆检索的推理感知重排序模型**（MemReranker: Reasoning-Aware Reranking for Agent Memory Retrieval）
🔗 https://arxiv.org/abs/2605.06132
📅 2026-05-07 | cs.CL

💡 **核心贡献**
针对 Agent 记忆"语义相关却不含关键信息"的检索痛点，提出 MemReranker 系列（0.6B/4B），基于 Qwen3-Reranker 通过多阶段 LLM 知识蒸馏（多教师对比软标签 + BCE 蒸馏 + InfoNCE 对比学习）训练出具备时序约束、因果推理和指代消解能力的轻量记忆重排序器。

🔧 **技术亮点**
- 多教师成对比较生成校准软标签，BCE 逐点蒸馏建立均匀分布分数，InfoNCE 对比增强难样本区分
- 训练数据融合通用语料与记忆专用多轮对话数据（含时序约束、因果推理、共指消解）
- MemReranker-0.6B 以极低延迟大幅超越 BGE-Reranker，达到开源 4B/8B 模型水平

📊 **实验结果**
- MemReranker-4B：MAP 0.737，部分指标与 Gemini-3-Flash 持平
- 推理延迟仅为大模型的 10-20%
- 金融、医疗垂直域基准上泛化能力与主流大参数重排序器相当

🧩 **技术分类**
Memory维度：记忆检索 / 外部存储

🔗 **Memory ↔ Context 关联**
高精度重排序直接决定"哪些记忆进入上下文"，MemReranker 通过推理感知过滤有效提升上下文利用率，是 Memory→Context 管道的关键质量门。

### 5

📄 **PEEK：面向长上下文 Agent 的方向感缓存（上下文地图）系统**（PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents）
🔗 https://arxiv.org/abs/2605.19932
📅 2026-05-19 | cs.AI / cs.CL / cs.LG

💡 **核心贡献**
针对 Agent 在文档库/代码仓库等重复性外部上下文中"每次重新定向"的低效问题，提出 PEEK：将对上下文的方向性知识（内容摘要、常用实体、历史有用 schema 等）维护为一个固定大小的"上下文地图"缓存，常驻 Agent prompt，实现跨次调用的持久化定向记忆。

🔧 **技术亮点**
- 三模块可编程缓存策略：Distiller（从推理时信号提取可迁移知识）+ Cartographer（结构化编辑）+ Evictor（优先级驱逐，固定 token 预算）
- 上下文地图是小型常量大小 artifact，不随轮次累积增长
- 跨 LM 和 Agent 架构泛化（含 OpenAI Codex 生产级 coding agent）

📊 **实验结果**
- 长上下文推理和信息聚合：比强基线提升 6.3–34.0%，迭代次数减少 93–145 次，成本比 ACE 低 1.7–5.8×
- 上下文学习任务：解题率提升 6.0–14.0%，Rubric 准确率提升 7.8–12.1%，成本比 ACE 低 1.4×

🧩 **技术分类**
Memory维度：语义记忆 / 工作记忆；Context维度：上下文压缩 / 上下文管理

🔗 **Memory ↔ Context 关联**
PEEK 本质是"跨会话的上下文持久化"——将历史上下文中的结构知识蒸馏为常驻记忆，在新轮上下文中直接复用，是 Memory 与 Context 协同设计最直接的体现。

### 6

📄 **ACON：面向长周期 LLM Agent 的上下文压缩优化框架**（ACON: Optimizing Context Compression for Long-horizon LLM Agents）
🔗 https://arxiv.org/abs/2510.00615
📅 2025-10-01（ICML 2026 accepted）| cs.AI / cs.CL

💡 **核心贡献**
针对长周期 Agent 任务中历史动作与观察不断累积导致上下文膨胀的问题，提出 ACON：统一压缩环境观察和交互历史，在自然语言空间通过对比失败轨迹迭代优化压缩指南，并将优化后的 LLM 压缩器蒸馏为小模型以降低开销。

🔧 **技术亮点**
- 压缩指南优化（Guideline Optimization）：给定完整上下文成功而压缩上下文失败的轨迹对，由大 LLM 分析失败原因并自动更新压缩规则
- 将优化后的 LLM 压缩器蒸馏到小模型，保持 >95% 精度的同时大幅降低推理开销
- 不要求模型参数更新，适用于专有和大规模 LLM

📊 **实验结果**
- AppWorld / OfficeBench / Multi-objective QA：内存使用减少 26–54%（峰值 tokens）
- 蒸馏小压缩器保留 >95% 精度
- 作为小 LM 的 Agent 能力增强：任务表现提升最高 46%

🧩 **技术分类**
Context维度：上下文压缩 / 长窗口扩展

🔗 **Memory ↔ Context 关联**
ACON 的压缩指南可视为 Agent 对"什么信息值得保留"的元记忆，将压缩策略本身编码为可进化的规则记忆，实现 Memory（压缩知识）→ Context（高效表示）的闭环。

## 🧠 今日洞察

1. **记忆存储范式多元化**：本周论文覆盖了记忆研究的完整谱系——从极端参数化（δ-mem 的 8×8 状态矩阵）、可执行知识图谱（EAM）到检索增强外部存储（Goal-Mem、MemReranker），研究趋势已从"选择哪种存储方式"演进为"如何组合多种存储机制"构建混合记忆架构。

2. **检索质量成为 Agent Memory 新瓶颈**：Goal-Mem 和 MemReranker 从不同角度直击同一痛点——"语义相关但不含关键信息"；前者通过逆向推理链改造检索策略，后者通过轻量重排序器注入推理能力，共同标志着 Agent Memory 研究重心从"如何存储"向"如何精准召回"转移。

3. **Memory × Context 协同设计成显学**：PEEK 和 ACON 分别代表"跨会话记忆复用上下文"与"压缩上下文以释放记忆空间"两种协同思路，两者都在试图打破上下文窗口的硬约束——未来高效 Agent 必然需要 Memory 与 Context 的联合优化，而非分别对待。
