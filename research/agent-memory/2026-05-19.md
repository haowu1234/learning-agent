### 1️⃣

📄 **【从存储到经验：LLM 智能体记忆机制演化综述】**（From Storage to Experience: A Survey on the Evolution of LLM Agent Memory Mechanisms）

🔗 https://arxiv.org/abs/2605.06716  
📅 2026-05-07 | ACL 2026 Findings

💡 **核心贡献**  
提出 LLM Agent 记忆机制的演化三阶段框架（存储 → 反思 → 经验），统一了操作系统工程派与认知科学派两种长期割裂的研究视角；在"经验"阶段重点阐释了主动探索与跨轨迹抽象两种前沿机制，给出下一代 LLM Agent 设计原则。

🔧 **技术亮点**
- **三阶段形式化定义**：Storage（轨迹保存）→ Reflection（轨迹精炼）→ Experience（轨迹抽象），每阶段建立严格的形式定义
- **跨轨迹抽象**：提炼多条历史轨迹中的共性策略，形成可复用的高阶经验表示
- **主动探索机制**：Agent 不再被动等待记忆触发，而是主动探索以构建前瞻性经验

📊 **实验结果**  
综述性工作，梳理 2022-2026 文献并提出统一框架，ACL 2026 Findings 录用

🧩 **技术分类**  
Memory 维度：情景记忆 / 语义记忆（记忆演化全维度）

🔗 **Memory ↔ Context 关联**  
记忆机制的"经验阶段"需要将跨轨迹的语义抽象注入上下文，实质上是将长期记忆压缩为可复用的上下文片段。

### 2️⃣

📄 **【EASM：面向超个性化的情感注意力有状态记忆架构】**（Emotion-Attended Stateful Memory (EASM): The Architecture for Hyper-Personalization at Scale）

🔗 https://arxiv.org/abs/2605.14833  
📅 2026-05-14

💡 **核心贡献**  
首次将情感信号作为记忆检索的核心权重维度，提出跨会话有状态记忆架构；通过情感标注增强长期历史与推断意图的融合，突破 LLM 跨会话无状态的本质限制，为超个性化 AI 提供基础设施层。

🔧 **技术亮点**
- **情感注意力检索**：在记忆写入时嵌入情感元数据，检索时以情感状态为权重进行动态重排序
- **有状态上下文构建**：推理阶段动态整合长期用户历史、情感信号和推断意图，实现跨会话连贯性
- **对抗性情感稳定性**：在悲伤、痛苦、不确定性等极端情绪场景下记忆机制仍保持稳定

📊 **实验结果**  
A/B 测试（30 段非脚本对话，6 种情感类别）：  
- 记忆接地（Memory Grounding）：+95%  
- 计划清晰度（Plan Clarity）：+57%  
- 情感验证（Emotional Validation）：+34%

🧩 **技术分类**  
Memory 维度：情景记忆 / 外部存储 / 记忆检索

🔗 **Memory ↔ Context 关联**  
情感标注的记忆在推理时被动态构建为有状态上下文窗口，是将长期记忆精准注入当前上下文的典型实现。

### 3️⃣

📄 **【ARPM：异构时序记忆治理框架——长期 LLM 人格一致性】**（A Heterogeneous Temporal Memory Governance Framework for Long-Term LLM Persona Consistency）

🔗 https://arxiv.org/abs/2605.14802  
📅 2026-05-14 | 开源：https://github.com/Spirtxiaoqi7/ARPM

💡 **核心贡献**  
将长期对话的人格一致性问题重新定义为"可追溯、可审计、可迁移的记忆治理问题"而非模型权重编码问题；通过静态知识记忆与动态对话记忆分离 + 混合检索 + 双时序重排序，在极端噪声和多模型交接环境下维持语义连贯性。

🔧 **技术亮点**
- **静态/动态记忆分离**：静态知识记忆（人格设定、事实知识）与动态对话经验记忆独立管理，避免相互污染
- **混合检索融合（Vector + BM25 + RRF + 双时序重排序）**：解决纯语义检索无法追溯和纠错的问题
- **受控分析协议（CAP）**：引入证据验证和答案绑定机制，实现白盒可审计的记忆治理

📊 **实验结果**  
- 510 万字符噪声基底下稳定维持记忆一致性  
- 禁用对话历史检索：准确率 100% → 66.7%  
- 禁用 BM25：准确率 100% → 80.0%（证明纯向量检索不足）  
- CSV 自动评判 vs. 人工审核在 1:5 噪声比下：54.0% vs. 100.0%

🧩 **技术分类**  
Memory 维度：语义记忆 / 外部存储 / 记忆检索  
Context 维度：上下文管理

🔗 **Memory ↔ Context 关联**  
ARPM 的核心机制是将治理后的记忆以受控方式注入上下文（CAP 协议绑定），Memory 治理质量直接决定上下文的可信度。

### 4️⃣

📄 **【CAST：基于案例的 LLM 工具调用自适应推理与执行校准】**（Case-Based Calibration of Adaptive Reasoning and Execution for LLM Tool Use）

🔗 https://arxiv.org/abs/2605.15041  
📅 2026-05-14

💡 **核心贡献**  
提出将历史执行轨迹视为结构化案例的 CAST 框架，从中提取"复杂度画像"和"失败画像"，驱动自适应推理策略选择；通过强化学习让模型自主内化基于案例的策略，在提升精度的同时减少冗余推理。

🔧 **技术亮点**
- **复杂度画像提取**：从历史案例中建模任务复杂度分布，指导最优推理深度选择（快速 vs. 慢思）
- **失败画像建模**：识别常见结构性错误类型，在执行前预警并规避
- **RL 驱动案例内化**：不是简单的 few-shot exemplar 复用，而是通过强化学习将案例知识内化为模型策略

📊 **实验结果**  
BFCLv2 和 ToolBench 评测：  
- 执行准确率提升：+5.85 pp  
- 平均推理长度减少：-26%

🧩 **技术分类**  
Memory 维度：情景记忆（执行轨迹案例库）

🔗 **Memory ↔ Context 关联**  
案例库作为外部情景记忆，在每次工具调用时动态检索相关案例注入上下文，是情景记忆驱动上下文适配的典型示例。

### 5️⃣

📄 **【为什么邻域很重要：Agentic GraphRAG 中的遍历上下文与溯源】**（Why Neighborhoods Matter: Traversal Context and Provenance in Agentic GraphRAG）

🔗 https://arxiv.org/abs/2605.15109  
📅 2026-05-14 | IJCAI-ECAI 2026 Workshop

💡 **核心贡献**  
将 GraphRAG 的引用忠实性从"来源支持"重构为"检索轨迹溯源"问题，发现未被引用的遍历上下文（即 Agent 访问但未直接引用的图节点）同样显著影响答案准确性，揭示了 Agent 记忆中的"隐性知识路径"现象。

🔧 **技术亮点**
- **轨迹级引用评估**：将 Agent 的图探索路径全程纳入忠实性评估，而非仅评估最终引用
- **受控消融实验**：分别对引用证据、未引用邻居实体、图结构进行隔离/移除/屏蔽对比实验
- **"遍历上下文"概念提出**：形式化定义了"有影响但未引用"的上下文，挑战现有 RAG 评估范式

📊 **实验结果**  
- 移除引用证据：答案显著改变，准确率明显下降（引用证据是必要条件）  
- 屏蔽未引用邻居实体：准确率同样下降（引用证据不充分）  
- 结论：知识图谱记忆检索的评估需要从点到轨迹全面升级

🧩 **技术分类**  
Memory 维度：外部存储 / 记忆检索（知识图谱）  
Context 维度：上下文管理

🔗 **Memory ↔ Context 关联**  
图遍历的完整轨迹（而非仅最终引用节点）构成了注入上下文的实质内容，记忆路径即上下文结构。

### 6️⃣

📄 **【DCRD：通过动态认知调和解码缓解 LLM 中的上下文-记忆冲突】**（Mitigating Context-Memory Conflicts in LLMs through Dynamic Cognitive Reconciliation Decoding）

🔗 https://arxiv.org/abs/2605.12185  
📅 2026-05-12 | 已录用：IEEE TASLP

💡 **核心贡献**  
提出两阶段动态解码方法 DCRD，通过注意力图分析预测上下文-参数记忆冲突，并自适应路由至不同解码路径（贪心解码或上下文保真度动态解码），在冲突场景下优先信任上下文，无冲突场景保持解码效率。

🔧 **技术亮点**
- **注意力图冲突预测**：分析 LLM 内部注意力分布，在解码前预判是否存在上下文-记忆冲突
- **双路径动态解码**：冲突预测正 → 上下文保真度动态解码（强化外部知识权重）；冲突预测负 → 贪心解码（保持效率）
- **ConflictKG 基准构建**：新构建知识冲突 QA 基准，模拟频繁知识更新场景

📊 **实验结果**  
4 个 LLM × 6 个 QA 数据集：DCRD 在所有基线上达到 SOTA，IEEE TASLP 录用

🧩 **技术分类**  
Memory 维度：语义记忆（参数记忆 vs. 外部知识）  
Context 维度：上下文管理 / In-Context 学习

🔗 **Memory ↔ Context 关联**  
DCRD 直接处理参数记忆（模型权重中的知识）与上下文知识之间的冲突协调，是 Memory 与 Context 矛盾最直接的解决方案。

## 🧠 今日洞察

1. **记忆治理工程化正成为主旋律。** 从 ARPM 的静态/动态记忆分离与可审计协议，到 CAST 的失败画像建模，研究正从"如何设计记忆模块"转向"如何在生产级噪声、多模型交接、上下文清除等极端条件下治理记忆系统"——Memory 已从原型功能进入工程基础设施阶段。

2. **情感维度与检索轨迹是记忆系统的两个被低估的方向。** EASM 证明情感信号可将记忆接地准确率提升 95%，而 Agentic GraphRAG 研究揭示了"遍历但未引用"的隐性上下文同样关键——当前主流的向量检索范式在这两个维度上存在系统性盲区。

3. **Memory 与 Context 的协同设计正从"先存后取"迈向"动态共演"。** DCRD 的参数记忆-上下文冲突解码、ARPM 的受控注入协议、EASM 的推理时有状态上下文构建，共同指向一个新范式：记忆不再是被动的后备知识库，而是与当前上下文实时协商、动态融合的认知基础设施。
