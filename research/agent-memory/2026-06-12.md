📄 **EvoArena：动态环境中追踪记忆演化的鲁棒LLM智能体框架**（EvoArena: Tracking Memory Evolution for Robust LLM Agents in Dynamic Environments）
🔗 https://arxiv.org/abs/2606.13681
💡 核心贡献：提出 EvoMem，一种基于补丁（patch）的记忆范式，将记忆演化记录为结构化的更新历史，使 Agent 能够通过追踪记忆变化来推理动态环境的演变；同时引入 EvoArena 基准测试，覆盖终端、软件、社交三大动态领域，专门评估 Agent 在持续变化环境下的适应能力。
🔧 技术亮点：
- **Patch-based Memory Paradigm**：将环境变化抽象为有序的内存更新补丁，而非覆盖式重写，保留完整演化轨迹
- **三域基准测试**：EvoArena 在 terminal、software、social-preference 三领域模拟渐进式环境更新，当前最优 Agent 平均准确率仅 39.6%
- **链级准确率提升**：EvoMem 在需要完成连续相关子任务的链式任务上提升 3.7%，表明结构化历史记忆有助于跨步推理
📊 实验结果：EvoMem 在 EvoArena 平均提升 1.5%；GAIA 基准提升 6.1%；LoCoMo 基准提升 4.8%；链级准确率提升 3.7%
🧩 技术分类：**Memory维度**：情景记忆 / 工作记忆 / 外部存储
🔗 Memory ↔ Context 关联：EvoMem 将历史记忆补丁结构化地注入上下文，让 Agent 在有限 context window 内高效访问演化轨迹，实现 Memory 到 Context 的精准投影。

📄 **通过检索增强强化微调学习类比推理**（Learning to Reason by Analogy via Retrieval-Augmented Reinforcement Fine-Tuning）
🔗 https://arxiv.org/abs/2606.13680
💡 核心贡献：提出 RA-RFT（检索增强强化微调），训练检索器以"推理收益"而非语义相似度对上下文排序，让 LLM 学习通过类比推理来解决复杂问题；核心洞察是相似问题可能需要截然不同的推理策略，而表面不相似的问题可能共享相同的推理模式。
🔧 技术亮点：
- **Gold-Relevance Distillation**：通过蒸馏训练检索器，使其按"推理期望收益"而非语义重叠排名候选样本
- **推理感知检索**：检索到的上下文（类比示例）为单个问题提供互补的解题策略和不同的推理脚手架
- **与 GRPO 互补**：RA-RFT 改进正交于奖励设计或训练课程，可叠加在现有强化微调方法之上
📊 实验结果：在 AIME 2025 上，Qwen3-1.7B 的 average@32 准确率比 GRPO 高 7.1 点，Qwen3-4B 高 2.8 点
🧩 技术分类：**Memory维度**：记忆检索；**Context维度**：In-Context学习
🔗 Memory ↔ Context 关联：RA-RFT 将外部示例库（记忆外存）转化为 in-context 类比演示，实现"按推理需求检索+填充上下文"的闭环，是 RAG 与 ICL 协同的典范。

📄 **Agents-K1：迈向Agent原生的知识编排**（Agents-K1: Towards Agent-native Knowledge Orchestration）
🔗 https://arxiv.org/abs/2606.13669
💡 核心贡献：构建端到端知识编排流水线 Agents-K1，将 246 万篇科学论文转化为 Agent 可直接推理的结构化知识图谱（Scholar-KG），解决现有 RAG 系统只用摘要、丢失关键实体/关系/证据的问题；提出 graphanything CLI 统一 Web 搜索、多模态图检索和跨文档遍历三种知识访问方式。
🔧 技术亮点：
- **五模块多模态解析器**：跨全文（非仅摘要）捕获实体、多模态证据、引用关系和类型化跨实体关系
- **GRPO 训练的4B信息抽取主干**：基于规则奖励的强化学习微调，提升结构化信息抽取精度
- **tri-source Agent 接口**：将 Web 搜索、图检索、跨文档遍历统一为单一工具调用接口，大幅降低知识访问复杂度
📊 实验结果：在科学信息抽取、知识图谱构建和多跳科学推理任务上均实现优越性能（详见论文）
🧩 技术分类：**Memory维度**：语义记忆 / 外部存储 / 记忆检索
🔗 Memory ↔ Context 关联：Agents-K1 将大规模外部语义记忆（知识图谱）通过结构化检索压缩为可装入上下文的精确子图，有效解决"知识量 vs 上下文长度"的根本矛盾。

📄 **HyperTool：超越逐步工具调用的工具增强 Agent**（HyperTool: Beyond Step-Wise Tool Calls for Tool-Augmented Agents）
🔗 https://arxiv.org/abs/2606.13663
💡 核心贡献：提出 HyperTool，将多个工具调用封装为单次可执行代码块（MCP 风格），让 Agent 在主推理上下文中只看到一次"超级工具"调用而非多次原子调用，从根本上解决"执行粒度不匹配"导致的上下文膨胀问题；在 MCP-Universe 基准上显著超越 GPT-OSS 和 Kimi-k2.5。
🔧 技术亮点：
- **Execution-Granularity Mismatch 识别**：明确指出逐步工具调用将确定性子流程暴露在模型可见的推理轨迹中，造成上下文浪费
- **合成 HyperTool 轨迹**：从跨工具组合任务中合成训练数据并在真实 MCP 环境中验证
- **局部中间值传递**：中间结果在代码块内部传递，不进入主推理轨迹，实现上下文天然压缩
📊 实验结果：Qwen3-32B 平均准确率从 15.69% → 35.29%；Qwen3-8B 从 9.93% → 33.33%；超越 GPT-OSS 和 Kimi-k2.5
🧩 技术分类：**Context维度**：上下文压缩 / 上下文管理
🔗 Memory ↔ Context 关联：HyperTool 通过在本地代码块内消化中间工具状态（工作记忆），只将最终结果写回主上下文，是工作记忆与上下文长度之间的高效折中方案。

📄 **EurekAgent：Agent 环境工程驱动的自主科学发现**（EurekAgent: Agent Environment Engineering is All You Need For Autonomous Scientific Discovery）
🔗 https://arxiv.org/abs/2606.13662
💡 核心贡献：将 Agent 能力提升的瓶颈从"工作流设计"重新定义为"环境工程"，提出 EurekAgent 沿四个维度（权限、制品、预算、人机协作）精心设计 Agent 执行环境，实现开放式探索与系统化制品管理；以不到 11 美元的 API 成本发现了新的 26 圆堆积问题最优解。
🔧 技术亮点：
- **Artifact Engineering**：基于文件系统和 Git 的协作机制，使多 Agent 可以系统化地共享、版本化和复用中间产物（即持久化的过程记忆）
- **Budget Engineering**：预算感知探索策略，防止无节制的上下文扩张和 API 消耗
- **权限隔离 + 人机协作**：隔离沙箱确保 Agent 执行安全，HITL 工程支持人类随时干预
📊 实验结果：在多项数学、内核工程、机器学习任务上取得新 SOTA；26 圆堆积问题发现成本 < $11
🧩 技术分类：**Memory维度**：外部存储（制品/Git）/ 情景记忆（探索历史）；**Context维度**：上下文管理
🔗 Memory ↔ Context 关联：EurekAgent 的制品工程将中间探索结果持久化为外部记忆（Git/文件系统），按需检索后注入 Agent 上下文，避免将完整探索历史撑爆 context window。

## 🧠 今日洞察

1. **Memory 的"演化性"成为新焦点**：从 EvoMem 的 patch-based 记忆更新，到 EurekAgent 的 Git-based 制品管理，研究者正在从"静态存储"转向"版本化、可追踪的动态记忆"，这与人类情景记忆的更新机制高度契合。

2. **Context 压缩的战场从内容转向结构**：HyperTool 的"工具级上下文折叠"和 Agents-K1 的"知识图谱子图检索"都指向同一趋势——减少上下文消耗不只靠压缩文本，而是从根本上改变信息以何种结构进入上下文。

3. **Memory ↔ Context 协同设计的最新进展**：RA-RFT 最具代表性地展现了协同设计的价值——外部记忆库（Experience Replay）通过推理感知检索精准填充 In-Context 示例，将 RAG 从"语义相似度匹配"升级为"推理需求驱动的记忆检索"，为 Memory × Context 协同优化树立了新的范式。
